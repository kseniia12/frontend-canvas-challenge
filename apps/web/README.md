# Канвас

Редактор на React Flow: текст, генератор, результат. Сохранение через REST, картинка тестовая с бэкенда.

## Запуск

Node 24, npm 11, из корня репозитория:

```sh
npm ci
npm run dev
```

Второй терминал:

```sh
npm run dev:web
```

Канвас: http://localhost:5174  
API: http://127.0.0.1:4001

`/api` и `/assets` проксируются на бэкенд. Сборка — `npm run build:web`, превью — `npm run preview:web`.

## Запросы и сохранение

`fetch` живёт только в `src/api/client.ts`. В отличие от магазина, ответы тут без обёртки `data`. Для PUT графа в заголовок кладётся ETag из предыдущего ответа (`If-Match`).

После правки жду 500 мс и отправляю последний снимок. Если человек ещё таскает ноды, пока ушёл PUT, следующий запрос ждёт новый ETag и уходит следом. Ответ старого сохранения в ноды не подмешиваю — на канвасе остаётся то, что сейчас на экране.

Генерацию жму только после сохранения. Если PUT не прошёл, запуск не стартую. На 412 черновик не выкидываю, можно явно забрать граф с сервера.

Повтор того же запуска генерации идёт с тем же Idempotency-Key. Новый запуск после отказа — новый ключ. Опрос обрывается, если ушли со страницы или job уже закончился.

## Граф

Индексы по id нод и рёбер обновляю, когда что-то добавили, удалили или связали. Пока ноду просто двигают, Map не пересобираю. Совместимость связи смотрю по этим индексам.

В PUT не отправляю служебное из React Flow (`selected`, `dragging` и т.п.) — перед сохранением один раз собираю чистый граф.

Картинку вешаю на `resultNodeId` из ответа. Если эту ноду уже удалили или переподключили цепочку, результат туда не ставлю.

## Что смотрела

Создание пространства, F5, три ноды и связи, debounce, генерация сразу после правки, отказ и повтор, картинка в результате.

## Чего нет

Undo и совместного редактирования нет. При конфликте версии не мержу два графа — либо оставляю свой черновик, либо беру сервер.

# @canvas/web

Редактор цепочки «текст → генератор → результат» на React Flow. Граф сохраняется через REST, генерация — тестовая.

## Запуск

Node.js 24.x и npm 11.x. Из корня репозитория:

```sh
npm ci
npm run dev
```

В другом терминале:

```sh
npm run dev:web
```

API: http://127.0.0.1:4001  
Канвас: http://localhost:5174

Vite проксирует `/api` и `/assets` на бэкенд.

Сборка:

```sh
npm run build:web
npm run preview:web
```

## Запросы

Ноды не вызывают `fetch`.

- `src/api/client.ts` — единственная отправка: URL, заголовки (`If-Match`, `Idempotency-Key`), 204/304 без JSON, ошибки.
- `src/api/errors.ts` — сеть / HTTP / разбор → `AppError`.
- `src/api/resources.ts` — path/method/тело. Новый метод API описывается здесь.
- `src/api/poll.ts` — опрос генерации с abort и проверкой «это всё ещё та же попытка».
- `src/store.ts` — debounce 500 мс, очередь PUT, конфликт 412, запуск генерации.

Ответы API без обёртки `data`. ETag берётся из заголовка и уходит обратно в `If-Match`.

## Debounce и очередь

Правка помечает граф грязным и сдвигает таймер. После паузы уходит один PUT последнего снимка. Пока PUT в полёте, новые правки копятся и уходят следующим запросом уже с новым ETag. Ответ старого PUT не записывается в ноды — локальный черновик главнее.

Кнопка генерации сбрасывает таймер, дожидается текущего PUT, при необходимости досылает хвост и только потом создаёт generation. Если сохранение упало, запуск не идёт.

`412` оставляет черновик на канвасе и предлагает перечитать сервер.

## Обработка графа

Индексы `Map` по id нод и рёбер пересобираются при добавлении/удалении/связях, не на каждый пиксель драга. `isValidConnection` смотрит в эти Map за O(1), без `.find` по массиву.

Снятие RF-полей (`selected`, `dragging`, `measured`) — один проход `toApiGraph` в момент сохранения, не на mousemove.

Итог генерации пишется в `Map(resultNodeId → job)`. Старый job не затирает более новый; картинка не ставится, если результат удалили или связь генератор→результат пропала.

## Что проверено

- создание пространства, F5 открывает тот же id
- три типа нод, перетаскивание, текст, связи только текст→генератор и генератор→результат
- один вход, у генератора один результат; удаление ноды снимает её рёбра
- debounce сохранения, статус «не сохранено / сохраняем / сохранено»
- генерация после несохранённой правки
- отказ и повтор, картинка в ноде результата
- опрос после F5, стоп при уходе со страницы

## Недоработки

Нет undo и совместного редактирования — в задании не требовались. Слияние двух версий при 412 не делается: оставляем черновик или берём сервер целиком.
